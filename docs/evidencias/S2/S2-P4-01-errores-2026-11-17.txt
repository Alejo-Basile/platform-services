- **Fecha:** 17/11/2026 (UTC-3).
- **Stack:** Compose `infra` con `doc-service@3887c29` reconstruido y
  `extraction-worker:sha-d3d8c80` (imagen publicada).
- **Comandos:**
  - `tests/e2e/errors/run.sh` → `PASS=7 FAIL=0 BLOCKED=1` (el bloqueo es el
    grupo de caos sin `--chaos`; los 3 casos worker quedaron desbloqueados).
  - `tests/e2e/errors/run.sh --chaos` → `PASS=10 FAIL=0 BLOCKED=0 KNOWN=1`.
  - `P4_STRICT_RELAY=1 tests/e2e/errors/run.sh --chaos` → `PASS=10 FAIL=0 KNOWN=0`
    (tras corregir el matcher del stream y con el catch-up de doc-service#83).

## Casos verdes con worker real

| Escenario | Estado final |
|---|---|
| oversize declarado | 400, sin documento persistido |
| MIME falso (no PDF) | `REJECTED` / `NOT_A_PDF`, sin mensaje en Redis |
| cliente que nunca sube | `PENDING_UPLOAD` (ventana corta) |
| PDF mayor al máximo en MinIO | upload 400/413, documento en `PENDING_UPLOAD` |
| MinIO caído | create/upload controlado y recuperación |
| PDF corrupto | `REJECTED` / `PDF_CORRUPT` |
| PDF cifrado | `REJECTED` / `PDF_ENCRYPTED` |
| PDF sin texto | `REJECTED` / `PDF_NO_TEXT` |
| Mongo caído | create 5xx y recuperación |
| Redis caído | recuperación, documento encolado (`KNOWN` si no reencola) |

Fixtures nuevos: `tests/fixtures/pdf/invalid/{corrupt,encrypted,no-text}.pdf`.

Los 3 casos de worker corren **antes** del bloque de caos: cortar Redis/Mongo
deja eventos sin encolar y el documento siguiente queda en `UPLOADED`, un fallo
en cascada que no dice nada del worker.

## Cierre: el relay sí reencola; el KNOWN era un falso negativo del arnés

La primera corrida estricta marcó `Redis caido` como fallo. La causa no era el
relay: `tests/e2e/lib.sh:stream_entries_for` buscaba el envelope JSON viejo
(`"document_id":"..."`) mientras el contrato vigente (ADR-0007) publica campos
planos, así que el matcher nunca encontraba la entrada aunque el relay la
hubiera creado. Los logs de doc-service lo mostraban encolando el documento
36 s después de volver Redis (al reabrirse el circuit breaker).

Corregido el matcher:

```
[errors] Redis caido
  [PASS] el relay encolo el documento tras recuperar Redis
  [PASS] Redis caido
[errors] Mongo caido
  [PASS] create con Mongo caido: HTTP 500 en 30s
  [PASS] Mongo caido

[errors] resumen: PASS=10 FAIL=0 BLOCKED=0 KNOWN=0
```

## Gap real encontrado y arreglado (doc-service#83)

Al reproducir el caos se encontró otra pérdida de eventos: cuando Mongo
reinicia y el watcher recibe `cannot resume stream`, descarta el token y abre
un stream fresco; el documento que ya estaba en `UPLOADED` no volvía a
aparecer hasta el reconciliador (hasta 30 min).

`doc-service#83` agrega un catch-up al abrir un stream sin token que procesa
los documentos en `UPLOADED`. Verificación en vivo: documento sembrado en
`UPLOADED` sin evento en el stream y token borrado → al arrancar,
`catch-up procesados=1`, el relay lo encola y termina en `COMPLETED` en 9 s.

## Resultado final

`S2-P4-01` queda verde con worker real y caos, en modo estricto.
