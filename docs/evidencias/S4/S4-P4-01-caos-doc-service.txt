Corrección y reverificación — 2026-11-17
---------------------------------------
La causa del FAIL histórico quedó confirmada: el arnés enviaba `INTERNAL_TOKEN`
de `infra/.env`, distinto del secreto montado en
`/run/secrets/internal_token` dentro de `doc-service`. El endpoint devolvía 401,
pero `reconcile_once` lo silenciaba con `|| true`; el ciclo de reconciliación
nunca se ejecutaba. En `--chaos1-kill` el documento quedaba QUEUED con Redis
detenido, por lo que la única recuperación válida era `sweepStuckQueued`.

Correcciones en el arnés:
- Se lee primero el secreto dentro de `doc-service`, se quitan CR/LF y se usa
  `env_value INTERNAL_TOKEN` solo como fallback; un token vacío falla en
  preflight.
- `reconcile_once` captura salida y exit code, informa fallos HTTP/error y
  rechaza respuestas sin `"lock_acquired":true`. El veredicto sigue dependiendo
  de la entrada única o la recuperación terminal observada.
- La limpieza limita a 15 s las llamadas Compose y la eliminación en MinIO.
- La primera corrida completa encontró además que envejecer `expires_at` en un
  documento QUEUED permite que el índice TTL lo borre. Se verificó el índice
  `expires_at_1` con `expireAfterSeconds:0`; para QUEUED/UPLOADED el arnés ahora
  envejece solo `updated_at`.

Bloqueo de entorno: purga de huérfanos y circuit breaker
--------------------------------------------------------
La causa de los HTTP 500 quedó diagnosticada en el stack: la policy MinIO
`docservice-rw` (`infra/compose/minio/init-buckets.sh:74`) no concede
`s3:DeleteObject`; solo permite `s3:GetObject`, `s3:ListBucket` y `s3:PutObject`.
Cada purga de objetos huérfanos del `doc-service` acumula aproximadamente 145
fallos con el mensaje literal `delete raw-pdfs/raw-pdfs/...: Access Denied`.
El fallo abre el circuit breaker compartido de MinIO; en los logs de
`infra-doc-service-1` se observó el estado `open`, y las solicitudes
`POST /api/v2/documents` y `GET /api/v2/documents/{id}/download` respondieron
HTTP 500 mientras permanecía abierto.

Impacto: las corridas de caos que coinciden con esa ventana pueden fallar antes
de inyectar el escenario, durante create o download. La decisión vigente del
usuario es no modificar infraestructura ni el breaker. Ante un HTTP 500 por
este bloqueo se espera aproximadamente 2 minutos, se reintenta una vez y, si
persiste, se registra como bloqueo de entorno, no como FAIL del escenario. No
se declara cerrado S4-P4-01 por este diagnóstico.
